# Universal Chunking Engine (.NET 9)

موتور قابل توسعه برای استخراج ساختار کتاب‌ها و آماده‌سازی متن برای RAG فارسی.

## امکانات
- معماری چندلایه Domain / Application / Infrastructure / API
- دریافت فایل‌های TXT، DOCX و PDF دارای لایه متنی
- نرمال‌سازی پایه فارسی و تشخیص زبان
- تشخیص تیترهای فارسی، عربی، انگلیسی و شماره‌گذاری سلسله‌مراتبی
- تشخیص پاراگراف، فهرست، نقل‌قول، پاورقی و نشانه‌های آیات
- حذف ورودی‌های فهرست مطالب DOCX بر اساس Style و Fieldهای استاندارد Word
- استخراج بهترین‌تلاش شماره صفحه DOCX از PageBreakهای صریح و LastRenderedPageBreak
- استخراج جدول‌های DOCX و حفظ ترتیب آن‌ها در کنار پاراگراف‌ها
- ساختار سلسله‌مراتبی فصل‌ها و بخش‌ها
- چانکینگ ساختاری با محدودیت اندازه، اندازه هدف و هم‌پوشانی محدودشده
- تولید بردار Dense با سرویس محلی BGE-M3 از طریق HTTP
- ذخیره بردارها، متن اصلی و فراداده ارجاع در Qdrant
- API برای بارگذاری، تحلیل ساختار، تولید چانک، تولید Embedding و ایندکس‌کردن سند

## تضمین حفظ متن منبع
در فرایند ایندکس، متن اصلی هر چانک بدون بازنویسی در payload مربوط به Qdrant ذخیره می‌شود. بردار فقط برای جست‌وجوی معنایی است. اطلاعاتی مانند نام فایل، عنوان سند، زبان، مسیر فصل، شماره چانک، محدوده کاراکتر و شماره صفحه نیز کنار متن ذخیره می‌شوند. هیچ OCR یا بازنویسی متنی در این فرایند وجود ندارد.

## عمداً خارج از محدوده
- **هیچ OCR در پروژه وجود ندارد.** PDF اسکن‌شده بدون لایه متنی استخراج نمی‌شود.
- اتصال به SQL Server، Reranker و Ollama در این نسخه انجام نشده است.
- راهبرد Adaptive فعلاً از پیاده‌سازی ساختاری پایه استفاده می‌کند. راهبردهای Semantic و Hybrid هنوز پیاده‌سازی نشده‌اند و انتخاب آن‌ها خطای صریح برمی‌گرداند.
- شمارش توکن فعلی تخمینی است و باید برای محدودیت دقیق مدل مقصد با tokenizer همان مدل جایگزین شود.
- جدول‌های PDF در این نسخه به‌صورت متن صفحه باقی می‌مانند و ساختار سلولی آن‌ها بازسازی نمی‌شود.
- صفحه‌بندی DOCX وابسته به Layout ذخیره‌شده در فایل است.

## پیش‌نیاز و اجرا
نیازمند .NET 9 SDK است. از پوشه ریشه اجرا کنید: dotnet restore، dotnet build، dotnet test و سپس dotnet run --project src/UCE.Api.

سرویس BGE-M3 باید جداگانه اجرا و در دسترس API باشد. تنظیمات آن در بخش BgeM3 فایل appsettings.json قرار دارد:
- BaseUrl: آدرس سرویس FastAPI (پیش‌فرض http://127.0.0.1:8000/)
- BatchSize: تعداد متن در هر درخواست (پیش‌فرض 8)
- Normalize: نرمال‌سازی بردار خروجی (پیش‌فرض true)
- TimeoutSeconds: مهلت درخواست (پیش‌فرض 300 ثانیه)

Qdrant نیز باید در دسترس API باشد. تنظیمات اتصال در بخش Qdrant:
- BaseUrl: آدرس Qdrant (پیش‌فرض http://127.0.0.1:6333/)
- CollectionName: نام Collection (پیش‌فرض uce_chunks)
- VectorSize: بُعد بردار (برای BGE-M3 برابر 1024)
- Distance: معیار فاصله (پیش‌فرض Cosine)
- UpsertBatchSize: تعداد Point در هر درخواست ذخیره‌سازی
- TimeoutSeconds: مهلت درخواست
- ApiKey: در صورت استفاده از Qdrant دارای احراز هویت، کلید را از User Secrets یا متغیر محیطی بخوانید و آن را در Git قرار ندهید.

## API
- GET /health
- POST /api/documents/analyze با multipart/form-data و فیلد file
- POST /api/documents/chunk با فیلد file و پارامترهای اختیاری targetTokens، maxTokens و overlapTokens
- POST /api/documents/chunk-embed: بردارهای BGE-M3 را در پاسخ برمی‌گرداند و ذخیره‌سازی نمی‌کند.
- POST /api/documents/index: سند را استخراج و قطعه‌بندی می‌کند، برای هر چانک با BGE-M3 بردار می‌سازد و متن اصلی به همراه اطلاعات ارجاع و بردار را در Collection تنظیم‌شده Qdrant ذخیره می‌کند. پاسخ شامل DocumentId، تعداد چانک‌ها و ابعاد بردار است.

Collection در اولین درخواست ایندکس، در صورت نبودن، به‌صورت خودکار با ابعاد و معیار فاصله تنظیم‌شده ایجاد می‌شود. هر سند با یک شناسه مستقل ذخیره می‌شود؛ شناسه در پاسخ برگردانده می‌شود تا در مراحل بعد برای فیلتر جست‌وجو و مدیریت اسناد استفاده شود.

## نکات دقت
1. TokenCount تخمینی است و معادل tokenizer اختصاصی مدل نیست.
2. تشخیص تیتر و نوع بلوک heuristic است و باید روی نمونه‌های واقعی کتاب ارزیابی و تنظیم شود.
3. ترتیب پاراگراف و جدول در DOCX در مدل بلوک‌ها حفظ می‌شود و جدول به‌صورت متنی وارد ساختار و چانک‌ها می‌شود.
4. موقعیت‌ها در متن استخراج‌شده ثبت می‌شوند و معادل offset بایت فایل اصلی نیستند.
5. فایل‌های ورودی باید از نظر اندازه و امنیت در لایه استقرار محدود شوند.
