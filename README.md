# Universal Chunking Engine (.NET 9)

موتور قابل توسعه برای استخراج ساختار کتاب‌ها و آماده‌سازی متن برای RAG فارسی.

## امکانات
- معماری چندلایه Domain / Application / Infrastructure / API
- دریافت فایل‌های TXT، DOCX و PDF دارای لایه متنی
- نرمال‌سازی پایه فارسی و تشخیص زبان
- تشخیص تیترهای فارسی، عربی، انگلیسی و شماره‌گذاری سلسله‌مراتبی
- تشخیص پاراگراف، فهرست، نقل‌قول، پاورقی و نشانه‌های آیات
- حذف ورودی‌های فهرست مطالب DOCX بر اساس Style و Fieldهای استاندارد Word
- استخراج بهترین‌تلاش شماره صفحه DOCX از PageBreakهای صریح و LastRenderedPageBreak
- استخراج جدول‌های DOCX و حفظ ترتیب آن‌ها در کنار پاراگراف‌ها
- ساختار سلسله‌مراتبی فصل‌ها و بخش‌ها
- چانکینگ ساختاری با محدودیت اندازه، اندازه هدف و هم‌پوشانی محدودشده
- API برای بارگذاری، تحلیل ساختار و تولید چانک
- تست‌های واحد برای تشخیص تیتر، ساختار سند، جدول، فهرست مطالب و شماره صفحه

## عمداً خارج از محدوده
- **هیچ OCR در پروژه وجود ندارد.** PDF اسکن‌شده بدون لایه متنی استخراج نمی‌شود.
- اتصال به SQL Server، Qdrant، BGE-M3، Reranker و Ollama در این نسخه انجام نشده است.
- راهبرد Adaptive فعلاً از پیاده‌سازی ساختاری پایه استفاده می‌کند. راهبردهای Semantic و Hybrid هنوز پیاده‌سازی نشده‌اند و انتخاب آن‌ها خطای صریح برمی‌گرداند؛ به‌اشتباه چانکینگ ساختاری اجرا نمی‌شود.
- شمارش توکن فعلی تخمینی است و باید برای محدودیت دقیق مدل مقصد با tokenizer همان مدل جایگزین شود.
- جدول‌های PDF در این نسخه به‌صورت متن صفحه باقی می‌مانند و ساختار سلولی آن‌ها بازسازی نمی‌شود.
- صفحه‌بندی DOCX وابسته به Layout ذخیره‌شده در فایل است. شماره صفحات استخراج‌شده از PageBreakهای صریح و LastRenderedPageBreak بهترین‌تلاش است و معادل صفحه‌بندی قطعی Word یا چاپ نهایی نیست؛ DOCX ممکن است هیچ‌یک از این نشانگرها را نداشته باشد.

## پیش‌نیاز و اجرا
نیازمند .NET 9 SDK است. از پوشه ریشه اجرا کنید: `dotnet restore`، `dotnet build`، `dotnet test` و سپس `dotnet run --project src/UCE.Api`.

## API
- `GET /health`
- `POST /api/documents/analyze` با `multipart/form-data` و فیلد `file`
- `POST /api/documents/chunk` با `multipart/form-data` و فیلد `file` و پارامترهای اختیاری `targetTokens`, `maxTokens`, `overlapTokens`

## نکات دقت
1. TokenCount تخمینی است و معادل tokenizer اختصاصی مدل نیست.
2. تشخیص تیتر و نوع بلوک heuristic است و باید روی نمونه‌های واقعی کتاب ارزیابی و تنظیم شود.
3. ترتیب پاراگراف و جدول در DOCX در مدل بلوک‌ها حفظ می‌شود و جدول به‌صورت متنی وارد ساختار و چانک‌ها می‌شود.
4. شماره صفحه DOCX فقط در صورت وجود نشانگرهای صفحه در فایل قابل استخراج است؛ برای صفحه‌بندی دقیق باید DOCX با موتور سازگار Word رندر شود.
5. موقعیت‌ها در متن استخراج‌شده ثبت می‌شوند و معادل offset بایت فایل اصلی نیستند.
6. فایل‌های ورودی باید از نظر اندازه و امنیت در لایه استقرار محدود شوند.
